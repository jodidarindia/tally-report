# FLOWRA Busy Sync Agent v1.7.0 — Build Notes
**Release date:** 1 Oct 2026
**Predecessor:** v1.6.2 (corrupt-memo resilient)
**Scope:** three customer-locked features in one release.

## What ships in v1.7.0

### 1. One-email-one-company binding (TOFU) — "Busy Company Lock"
- Keyed on **`Cmpny.BDEPName`** (user's choice `1-b`). Case- & whitespace-insensitive compare.
- On startup, after `_resolve_company_display_name()`, the agent calls `POST /api/agent/busy-binding/check` with `{tenant_id, sync_token, busy_company_name}`. Response: `{bound, matches, existing_name}`.
  - **matches:true** → enter the sync loop normally.
  - **bound:false** → let the first full sync TOFU-bind on the server side.
  - **matches:false** → log `[daemon] BUSY-BIND MISMATCH: …`, emit a `busy_binding_mismatch` progress event (GUI subscribes to this), set the status bar message, and go to a 60-second sleep loop (process stays alive so the admin can read the dialog). **DOES NOT enter sync loop.**
- Server-side `validate_busy_sync()` is called from `/api/agent/sync` whenever the payload is from the Busy agent (`source=="busy"` OR `busy_company_name` present) — belt-and-braces so the hard-block fires even if the agent skips the pre-check.
- Useradmin can unbind from **Flowra → Settings → Integrations → Busy Company Lock** — existing synced data is retained; next successful sync re-binds (TOFU).

### 2. Station field → Repeat Order · City (new Salesman sub-tab)
- Agent already extracts `Master1.Station` for every customer and ships it under the `station` key.
- New backend endpoint `GET /api/salesman-orders/city-suggestions?customer_name=X&company_id=Y`:
  - **City-popularity window:** last 90 days (query: `city_days=90`).
  - **Customer-not-bought window:** last 180 days (`customer_days=180`).
  - **Min city buyers to show an item:** `≥1` (user's choice `3b-iii` — noisy but exhaustive).
  - If the selected customer has no Station, response is `{reason: "no_station"}` → UI shows "Set this customer's city in Busy and re-sync to enable city-wise suggestions."
  - Each suggestion carries `city_buyers`, `top_city_customers` (first 3), `last_city_sale_date`, `customer_lapsed` flag.
- Salesman UI: new **"Repeat · City"** sub-tab between "Repeat Order" and "Suggestions" on the New Order form (`SalesmanOrderApp.js`).

### 3. Triple-name mapping — `ItemName / AliasName / PrintName`
- Agent now ships **all three** Busy name variants per stock item: `item_name`, `item_alias`, `item_print_name`.
- Backend module `routes/busy_settings.py`:
  - `GET /api/settings/busy-name-mapping` → returns the current mapping (defaults: `{flowra_name: ItemName, flowra_part_number: AliasName}`).
  - `PUT /api/settings/busy-name-mapping` → useradmin updates it.
  - `apply_busy_name_mapping(items, mapping)` is called from `/api/agent/sync`'s inventory branch when `source=="busy"` — rewrites each row's `item_name` and `part_number` according to the admin's chosen Busy field.
- Frontend: new **"Busy Field Mapping"** card on the Integrations tab with two dropdowns (`ItemName / AliasName / PrintName / none`). Changes take effect on the next Busy sync tick — no .exe rebuild or re-install.

## Rollout checklist
1. `cd desktop-agent\build-kit-busy && build.bat` → produces `FlowraBusyAgent_v1.7.0.exe`.
2. Upload the .exe, fill `sha256` + `size_bytes` in `backend/agent_release_busy.json`.
3. **NAVDURGA** (and every Busy tenant) auto-updates on the next 20-min cycle.
4. Flowra admins will see three new cards on **Settings → Integrations**: Google Drive, Busy Company Lock, Busy Field Mapping. Default mapping (`ItemName → name`, `AliasName → part_number`) matches v1.6.2's hard-coded behaviour, so no immediate action is needed.
5. Salesman app: pick any customer → the "Repeat · City" sub-tab appears next to "Repeat Order". Customers with no Station in Busy see a prompt; the admin can set the station in Busy at any time and the next 20-min sync picks it up.

## Rollback
- **Binding** → useradmin unbinds from Flowra UI; agent re-TOFUs on next sync.
- **Mapping** → useradmin flips the dropdowns; next inventory tick re-applies with the new choice.
- **City tab** → nothing to roll back — it's additive and safely empty when there's no station data.
