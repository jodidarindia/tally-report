# FLOWRA Busy Sync Agent v1.6.2 — Corrupt-Memo Resilience Notes
**Release date:** 1 Oct 2026
**Predecessor:** v1.6.1 (StockGroup name fix)
**Symptom:** Agent aborted at Phase 1/15 with `TypeError: 'NoneType' object is not subscriptable` deep inside `access_parser._parse_memo`.
**Reporter:** NAVDURGA AUTO SPARES JABALPUR / rypkeshav@gmail.com

## Root cause
From the customer's agent log:

```
[WARNING] Could not find overflow record data page overflow pointer: 0
[ERROR] Full sync failed
File "access_parser\access_parser.py", line 548, in _parse_memo
TypeError: 'NoneType' object is not subscriptable
```

One row in `COMP0001 NAV 26-27\db.bds :: Master1` has a memo (long-text) field whose **overflow pointer is 0** — meaning the library needs to follow a data-page pointer to read the memo's continuation, but the pointer points to no valid page. The library's `_parse_memo` fetches that page, gets `None`, and then subscripts it blindly → crash.

In v1.6.1 the exception propagated all the way up:

```
run_daemon → run_full_sync → sync_generator → extract_customers
    → _load_code_map → iter_rows("Master1") → _load_table_via_ap
    → self._ap.parse_table("Master1") → _parse_memo  ← CRASH
```

So one bad memo in `Master1` killed the entire sync at Phase 1/15 and the agent never attempted creditors, inventory, vouchers, ledgers, P&L.

## Fix (v1.6.2) — three layers of defence

### Layer 1 — monkey-patch `_parse_memo` at import
Installed exactly once per process via a module-level sentinel (`_flowra_memo_patch_installed`). The wrapper calls the original and swallows `TypeError / IndexError / AttributeError / KeyError / ValueError`, logging at DEBUG so a sync of 50k rows with one corrupt memo doesn't flood the log. Returns `""`.

```python
_original_parse_memo = _ap_mod.AccessTable._parse_memo
def _safe_parse_memo(self, *args, **kwargs):
    try:
        return _original_parse_memo(self, *args, **kwargs)
    except (TypeError, IndexError, AttributeError, KeyError, ValueError) as e:
        logger.debug(f"[access_parser.patch] skipped corrupt memo cell: {type(e).__name__}: {e}")
        return ""
_ap_mod.AccessTable._parse_memo = _safe_parse_memo
```

### Layer 2 — wrap `parse_table()` in `_load_table_via_ap`
If the library crashes on a different internal path for a future customer DB (overflow page, LVAL inline chunk, unexpected column type), the WHOLE table is treated as empty for the current cycle. Next sync will retry. The sync must NEVER abort the entire company because one table has a bad row.

### Layer 3 — isolate each sync phase
Each of the 15 phases (customers → sundry_creditors → inventory → sales → receipts → payments → credit_notes → journals → sundry_journals → purchases → debit_notes → …) now runs inside its own try/except. If one extractor raises an unforeseen exception, we log it, emit a `phase_failed` progress event, mark the overall sync as failed, and **move on to the next phase**. The remaining phases contain the data admins actually care about for reports.
