# FLOWRA Tally Sync Agent v9.8.32 — Build Notes
**Release date:** 27 Sep 2026
**Predecessor:** v9.8.31 (multi-company-safe, name-based preflight)

## What's new

### GUID-bound Trust-On-First-Use (TOFU) sync — iter-168
- **Problem it fixes:** on any PC where the operator has more than one Tally company loaded, the SVCurrentCompany preflight from v9.8.31 is *advisory* (fails open on server errors). If the useradmin mistakes the FOREGROUND company or renames a company, cross-company vouchers can still bleed into the wrong FLOWRA workspace. Krishna Sales Corporation flagged this scenario.
- **What's added:**
  - New `TallyCollectionClient.fetch_company_guid(company_name)` — issues an `SVCURRENTCOMPANY`-scoped Collection request that pulls Tally's immutable per-company `$Guid` (survives rename & backup/restore). Returns normalised `str` (lowercase, brace-stripped).
  - New `TallySyncAgent._ensure_tally_binding(name, guid)` — calls `/api/agent/tally-binding/bind` on every cycle. Idempotent for the same GUID; server hard-refuses a *different* GUID. Non-fatal — the sync payload still carries the GUID and the backend's TOFU logic will bind on first successful write.
  - Both sync loops (`_quick_sync_cycle` and `_full_sync_cycle`) capture `_active_company_guid` at the company boundary. Every sync payload (`sync_to_backend`) and every progress heartbeat (`report_progress`) now include `company_guid`.
  - Version bump: `9.8.31-multi-company-safe` → `9.8.32-multi-company-guid-bound` (GUI banner + payload `agent_version`).
- **Backend contract (must be at least matching build):**
  - `POST /api/agent/tally-binding/bind` (sync_token auth) — idempotent same-GUID, refuses different-GUID.
  - `POST /api/agent/sync` — auto-binds first GUID (TOFU); hard-blocks GUID mismatch and blocks legacy agents without GUID once a binding exists.
  - `GET/DELETE /api/settings/tally-binding` (JWT admin) — Settings → Integrations page shows bound company + Unbind button.

## Build steps (Windows)
1. Open `build-kit\` in an elevated PowerShell / cmd.
2. `pip install -r requirements.txt`
3. `build.bat`
   → produces `dist\FlowraTallyAgent.exe`
4. Rename to `FlowraTallyAgent_v9.8.32.exe`, upload to the FLOWRA Setup-page release manifest (`agent_release.json`).
5. Update `agent_release.json` `version`, `sha256`, `size_bytes`, `released_at`.

## Rollback
If the binding logic misbehaves for a specific tenant, the useradmin can `DELETE /api/settings/tally-binding` from the Settings UI to clear the anchor — synced data is retained and the next sync will re-bind (TOFU) whatever GUID the agent now reports.
